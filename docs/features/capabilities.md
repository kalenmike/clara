| Budgets          | Turn, tool-call, wall-clock, and attempt limits are hard caps in every enforcement mode, including `observed`; an exhausted budget denies further work tools but keeps the Clara control tools available, records one `budget.exhausted` event per attempt, reserves the final 8% of the token budget (capped at 10k tokens) for the worker's report, keeps a valid result that arrives over budget instead of retrying the step, and retries a step that opts into `limits.on_exhausted: fail` when a budget denial cut the worker short, carrying its partial result into the next attempt. ## Adapter installation

`@clara/adapter` installs one or more harness bindings, registers the MCP bridge
per selected harness, and installs one shared standalone runner per workspace.
The OpenCode binding installs a `clara` primary agent and disables the plugin's
embedded runner so the shared runner is the only script executor. Agent and
router claims are scoped to the harness that owns the run or the adapter pinned
by `requires.adapter`; script claims stay shared so one runner serves every
harness in the workspace.

## Partial

- **Clara Lab** previews files on the lab host and probes through the running
  service. The host path is editable in Settings, including through a native
  folder picker; the service reports its own workspace. A containerized service
  with a different mount can still differ. Targets are enumerated for the root
  package and its direct imports, and source view caps at 512 KB. The Sessions
  view reads the newest 100 OpenCode sessions plus any session seen on the live
  event stream; it does not paginate or control sessions yet.
- **Session list** returns the newest 50 sessions; there is no infinite scroll.
- **Chat history** loads the newest 100 messages first and fetches older pages
  as the conversation is scrolled toward the top.
- **Command preview** shows only the name and description because the server does
  not expose command templates.
- **Plan** reads the newest completed `todowrite` tool call. The OpenCode server
  must enable the experimental todo tool (`experimental.todo`) or the section
  stays empty and Request Plan cannot create a list. Forked sessions hide the
  parent's checklist client-side; the copied call cannot be removed from the
  transcript.
- **Mentions** insert `@path` text references; they do not upload file contents.
- **Git changes** are read-only statistics for the working tree, the last three
  commits, or the branch base; there is no patch review.
- **Connection** holds one server at a time; there are no saved profiles.
- **Remote access** broadcasts each agent frame to every client in the room;
  there is no per-client routing or message backlog.
- **Pairing** gives each device its own revocable key and uses a one-time
  enrollment token. The relay client token is still shared. Revoking a device
  removes its key, live sessions, and push subscriptions.
- **Push** requires the home agent and a browser push endpoint; it does not
  replay events missed while the agent is down.
  Mobile devices are held while a visible desktop client is recently active, and
  there is no manual "send to phone" override.
- **E2EE** has no forward secrecy; each device key protects that device's
  sessions.
- **Git history** runs one fixed `git log -n 10` with a machine-readable
  `--format` in the session's directory and only through the home agent, where
  the admin shell policy applies. Rows preview conventional headers and expand
  to the author date, author, co-authors, and message body. The policy is a
  guardrail, not a sandbox: it does
  not restrict file writes, agent prompts, plugin RPC, or any other OpenCode
  API.

## Not built

- Pairing expiration, one-time codes, or scanning a QR from a saved screenshot
- Per-device keys or revocation
- Message backlog or offline delivery
- Full diff review, staging, committing, worktree management, interactive
  PTY/terminal sessions, MCP and plugin management. The pair terminal is a
  read-only emulation, not an interactive shell.
- A sandbox for command execution, or a positive allowlist of every proxied
  OpenCode route
- Simultaneous connections to multiple servers
- Session sharing, export, or import
- Per-project or per-kind push filtering
- Fetching OpenCode Go allowance or remaining usage limits
- A namespace picker, per-device namespaces, or a conflict-resolution UI for
  client settings sync
