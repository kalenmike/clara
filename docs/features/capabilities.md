## Partial

- **Session list** returns the newest 50 sessions; there is no infinite scroll.
- **Chat history** loads the newest 100 messages first and fetches older pages
  as the conversation is scrolled toward the top.
- **Command preview** shows only the name and description because the server does
  not expose command templates.
- **Plan** reads the newest completed `todowrite` tool call. The OpenCode server
  must enable the experimental todo tool (`experimental.todo`) or the section
  stays empty and Request Plan cannot create a list. Forked sessions hide the
  parent's checklist client-side; the copied call cannot be removed from the
  transcript.
- **Mentions** insert `@path` text references; they do not upload file contents.
- **Git changes** are read-only statistics for the working tree, the last three
  commits, or the branch base; there is no patch review.
- **Connection** holds one server at a time; there are no saved profiles.
- **Remote access** broadcasts each agent frame to every client in the room;
  there is no per-client routing or message backlog.
- **Pairing** shares one PSK and one client token across all paired devices; there
  is no per-device revocation. Rotating the pairing key clears all push
  subscriptions.
- **Push** requires the home agent and a browser push endpoint; it is unavailable
  in direct HTTP mode and does not replay events missed while the agent is down.
  Mobile devices are held while a visible desktop client is recently active, and
  there is no manual "send to phone" override.
- **E2EE** has no forward secrecy; the long-term PSK protects every session.
- **Git history** runs one fixed `git log -n 10` with a machine-readable
  `--format` in the session's directory and only through the home agent, where
  the admin shell policy applies. Rows preview conventional headers and expand
  to the author date, author, co-authors, and message body. Direct connections
  show an unavailable state. The policy is a guardrail, not a sandbox: it does
  not restrict file writes, agent prompts, plugin RPC, or any other OpenCode
  API.

## Not built

- Pairing expiration, one-time codes, or camera scanning inside the web app
- Per-device keys or revocation
- Message backlog or offline delivery
- Full diff review, staging, committing, worktree management, interactive
  PTY/terminal sessions, MCP and plugin management. The pair terminal is a
  read-only emulation, not an interactive shell.
- A sandbox for command execution, or a positive allowlist of every proxied
  OpenCode route
- Simultaneous connections to multiple servers
- Session sharing, export, or import
- Push notifications in direct HTTP mode
- Per-project or per-kind push filtering
- A namespace picker, per-device namespaces, or a conflict-resolution UI for
  client settings sync
